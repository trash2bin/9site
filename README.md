# Ivan's Little Web

Статичный сайт в эстетике персонального Web 1.0: GIF-фактуры, кнопки 88×31, кривые рамки, гаражный каталог.

В браузере работают только HTML и CSS. Go нужен как локальный сервер, Node — только для линтеров. Ни сборки, ни фреймворков, ни внешнего runtime: без Node сайт полностью работоспособен.

Репозиторий: <https://github.com/trash2bin/9site>.

![Скриншот главной страницы](docs/preview.webp)

## Запуск

Нужен [Go](https://go.dev/dl/) 1.24 или новее.

```bash
go run .
```

Открой `http://localhost:8080`, останови по `Ctrl+C`. Порт 8080 захардкожен в `main.go`.

Сборка и фоновый запуск на macOS:

```bash
go build -o site-server .
nohup ./site-server > server.log 2>&1 < /dev/null &
echo $! > server.pid
kill $(cat server.pid)          # остановить
```

## Проверки

```bash
npm install                     # ~120 пакетов, один раз, только для разработки
npm run lint                    # формат + CSS + Go + бюджет
npm run fix                     # форматирование и автоисправления
```

| Команда                | Что делает                                     |
| ---------------------- | ---------------------------------------------- |
| `npm run format`       | Prettier: HTML, CSS, JSON, YAML, Markdown      |
| `npm run format:check` | То же, ничего не меняя (режим CI)              |
| `npm run lint:css`     | Stylelint по `style.css`                       |
| `npm run lint:go`      | `gofmt -l` и `go vet ./...`                    |
| `npm run size`         | Сумма `index.html` + `style.css` против лимита |

Три настройки легко ломаются случайной «починкой»:

- **`printWidth: 120`.** На 80 символах HTML раздувался с 25 КБ до 36 КБ, на 120 прибавляет 4 КБ.
- **`htmlWhitespaceSensitivity: "css"`.** Расстояния в `.parts-grid`, `.tux-strip`, `.banner-strip` и `.swag-banners` задавали пробелы в разметке между `inline-block`; Prettier их переставляет, поэтому у прижатых контейнеров `font-size: 0`, а размер возвращают дочерние элементы. Геометрия сверена по ~100 элементам.
- **Стилевые правила Stylelint отключены.** На `stylelint-config-standard` было 177 замечаний, 109 — `declaration-block-single-line-max-declarations`, то есть война с «одна строка = одно правило», а Prettier делал только хуже. Остались опечатки в свойствах, неизвестные единицы, дубликаты селекторов.

`assets/` исключён из Prettier: там бинарные GIF и написанные вручную SVG.

## Как оно устроено

### Страница

`index.html` — единственная страница, якоря: `#content`, `#about`, `#interests`, `#journal`, `#consoles`, `#parts`, `#links`, `#guestbook`, `#rotation`. Каталог — 30 карточек статическим HTML: цены, артикулы и ссылки прописаны вручную, кнопки ведут на `mailto:`. В футере вместо числа визитов метка `<!--visits-->`; без сервера на месте цифр пусто, остальное работает.

### Стили

GIF-фактуры, SVG-паутина в углах, наклейки по краям, рамки `ridge`/`outset`/`inset`/`groove`, наклоны секций, адаптив. Роли шрифтов: `Press Start 2P` — шапка, `Pixelify Sans` — меню и служебные подписи, `Marker Felt`/`Palatino Linotype` — заголовки, `Comic Sans MS` — основной текст; разнобой шрифтов в карточках каталога намеренный.

Оба пиксельных шрифта нарезаны на латиницу и кириллицу двумя файлами, и выбор решает `unicode-range` в `@font-face`: объявишь один файл — половина текста уедет в системный шрифт. `VT323` без кириллицы и неиспользуемый `Special Elite` удалены, `Marker Felt` и `Comic Sans MS` — системные, кириллица у них в комплекте.

### Сервер

Только стандартная библиотека. Наружу открыты `index.html`, `style.css` и `assets/` (список задаёт `allowedStatic`), остальное отдаёт 404. Путь нормализуется через `path.Clean` **до** проверки префикса, поэтому `/assets/../main.go` и закодированные `%2e%2e` тоже закрыты (проверено). Главную отдаёт отдельный обработчик: читает `index.html`, подставляет счётчик, отправляет ответ. Файл на диске не меняется, поэтому `index.html` открывается и без сервера.

### Счётчик визитов

Единственное живое место на сайте: `main.go` меняет метку `<!--visits-->` на `<span>` с числом. Число лежит в файле — в проде `/var/lib/9site/visits.dat`, локально `visits.dat` рядом с бинарником, путь переопределяется через `VISITS_FILE`. Пишется на каждый заход через временный файл и `os.Rename` — переименование в пределах одной файловой системы атомарно, половинчатого файла не останется. Счёт переживает перезапуск, а 30 параллельных запросов дают прирост ровно 30 (проверено). Битый или отсутствующий файл не мешает запуску: сервер пишет в лог и считает с нуля. До пяти знаков число добивается нулями, ответ идёт с `Cache-Control: no-store`. В `deploy/9site.service` для записи добавлены `StateDirectory=9site` и `Environment=VISITS_FILE=...`: при `ProtectSystem=strict` это единственный каталог, доступный сервису на запись. Наружу файл не отдаётся. Базы данных, API и авторизации нет.

### Бюджет размера

`scripts/check-size.sh` следит за суммой `index.html` + `style.css`: сейчас 50 000 B при лимите 61 440 B. Лимит задаётся через `SIZE_LIMIT`, например `SIZE_LIMIT=30720 npm run size` — строгая проверка на 30 КБ. Исходное ТЗ просило именно 30 КБ, порог поднят осознанно; чтобы вернуться, резать надо длинные абзацы в `#rotation` — они занимают больше половины страницы.

## CI/CD

Два джоба в `.github/workflows/ci.yml`. **`checks`** — на пуш в `main`, на pull request и вручную: `npm ci`, `prettier --check`, `stylelint`, `gofmt`, `go vet`, `go build`, бюджет размера. **`deploy`** — за проверками, только при пуше в `main`: сборка под Linux с `-trimpath -ldflags="-s -w"`, rsync статики и бинарника, перезапуск сервиса, а после — проверка кодов ответов и счётчика (два запроса к главной, число должно вырасти ровно на единицу). Деплой молчит, пока не выставлена переменная `DEPLOY_ENABLED=true` и не заполнены секреты.

**Variables** (Settings → Secrets and variables → Actions):

| Переменная           | Значение                                    |
| -------------------- | ------------------------------------------- |
| `DEPLOY_ENABLED`     | `true`, когда сервер готов принимать деплой |
| `DEPLOY_RESTART_CMD` | команда перезапуска сервиса, необязательна  |

**Secrets:**

| Секрет            | Значение                                            |
| ----------------- | --------------------------------------------------- |
| `SSH_HOST`        | адрес сервера                                       |
| `SSH_PORT`        | порт SSH, обычно `22`                               |
| `SSH_USER`        | пользователь деплоя                                 |
| `SSH_PRIVATE_KEY` | приватный ключ целиком, со строками `BEGIN` и `END` |
| `DEPLOY_PATH`     | абсолютный путь, например `/var/www/ivan-web`       |

На сервере нужны только `rsync` и `sshd`, публичную часть ключа — в `~/.ssh/authorized_keys` пользователя деплоя. Без `DEPLOY_RESTART_CMD` деплой обновит файлы, но сервис придётся перезапускать вручную.

## Ассеты

Всё скачано и лежит локально, с CDN во время работы ничего не подгружается: фактуры TextureTown, кнопки 88×31 из коллекции DABAMOS (Telegram, Spotify, GitHub, Steam, Reddit, Twitter), фотографии консолей и автодеталей с Wikimedia Commons, шрифты Press Start 2P и Pixelify Sans по два файла, GIF с Tux с Tenor, обложки альбомов 9mice и Kai Angel.

Обложки — чужая интеллектуальная собственность: локально это неважно, при публикации вопросы могут возникнуть у правообладателя. Кнопки DABAMOS автор разрешает копировать себе, но просит не хотлинкать, файлы лежат в `assets/ico/`.

## Ограничения

- Порт 8080 захардкожен, HTTPS и домена нет.
- Базы данных нет, форма гостевой книги — ссылка на email.
- В блоке SWAG CONNECT шесть профилей ведут на настоящие аккаунты (Telegram, Spotify, GitHub, Twitter, Reddit, Steam): текстового списка с адресами нет, ссылки лежат в `href` кнопок 88×31.
- Счётчик считает заходы, а не посетителей: `F5` увеличивает число, защиты от накрутки нет.
- Каталог демонстрационный, заказы не оформляет.
- Часть картинок тяжелее 50 КБ, хотя ТЗ просило ужимать каждую до этого предела: `car-parts.png` (862 КБ), `junkyard-engines.jpg` (735 КБ), `avatar-anime.gif` (649 КБ), `kaiangel-album-shh1.jpg` (578 КБ), `console-3ds.jpg` (430 КБ).
- React/TypeScript из старой версии лежат отдельно в `web1-personal-site-ts-backup`, текущая версия их не использует.
